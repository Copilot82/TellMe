# Политика безопасности

## Статус документа

Политика относится к версии исходного кода, указанной в опубликованном release. Публичный график
обновлений, сроки исправлений и security SLA не устанавливаются. Наличие release не означает, что
реализация прошла независимый криптографический аудит.

Организация, использующая код в собственном контуре, принимает ответственность за fork,
dependency updates, аудит, управление ключами, incident response и исправления.

## Сообщение о существенной проблеме

Не публикуйте действующие credentials, private keys, seed-фразы, device tokens, персональные данные
или способ эксплуатации в открытом GitHub issue/discussion. Community-функции repository должны
быть отключены.

Если в GitHub включён **Private vulnerability reporting**, приватный отчёт можно отправить через
**Security → Report a vulnerability**. Наличие этого канала не означает SLA, обязательство ответа,
исправления или выпуска новой версии.

В безопасном отчёте достаточно указать:

1. затронутый commit;
2. предусловия и минимальный воспроизводимый сценарий;
3. влияние на confidentiality, integrity и availability;
4. redacted evidence без production secrets;
5. возможное исправление, если оно известно.

## Известные ограничения

- протокол и реализация не проходили независимый security audit;
- сервер видит routing metadata, перечисленные в `docs/threat-model.md`;
- защита сетевой анонимности не является целью проекта;
- компрометация разблокированного устройства находится за пределами части гарантий;
- одноузловой Compose требует инфраструктурной адаптации для high availability;
- автоматическая проверка dependencies не заменяет оценку применимости новых уязвимостей к
  конкретному контуру эксплуатации.

Модель доверия для версии `2.0.0`: [docs/threat-model.md](docs/threat-model.md).
